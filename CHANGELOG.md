# Changelog

ProfitShare is built in the open by Cris Graves, with Claude doing the typing, while she budgets and schedules her first feature. This log is kept by day so anyone picking the project up can see what changed and why. Newest day first. Commit hashes are on `main`.

The app is local-first: your project lives in your browser and in the `.profitshare.json` files you download. Nothing here changes a saved file without saying so.

## 2026-11-19

Work done overnight from the audit's "soon after launch" list.

- **Tables on a phone.** A table too wide for the screen now scrolls sideways inside its own box, on every tab. Numbers, money and short words are never broken across lines. The browser walk fails if a money value in any table wraps at phone width.
- **Easier to read.** Text that was too faint in Day or Night now meets the AA contrast standard, with the palette kept: the sienna on Day is a shade deeper, the red on Night a shade lighter.
- **Keyboard.** The focus ring shows on Day's paper. Budget categories and accounts open with Enter. Pop-outs take focus and hand it back when closed. Still mouse-only: adding a calendar event by clicking a day, and dragging strips, days and cast rows.
- **AI assist picks its own model.** If you have not chosen a model, the app uses the newest mid-priced one your key offers, and a model you chose is never changed. If your choice is no longer offered, the app says so beside the picker.
- **A plain note beside the key.** The key is kept in this browser, not encrypted, and goes only to Anthropic when you press an AI button.
- **About tab.** What ProfitShare is and is not, plus links to report a problem and read the code.
- **Rates that say when they are stale.** From 1 July 2027 the SAG tier and Deal tabs say the SAG-AFTRA rates were due to rise.
- **The repo has the files a public project needs.** CONTRIBUTING.md says how to run the checks and the rules a change must keep. SECURITY.md says how to report a problem privately through GitHub. There is a short code of conduct, forms for bugs and ideas (the bug form asks for steps on the sample film and warns against attaching a real budget), and a pull request checklist.
- **The project file has a written rule for change.** `docs/file-format.md` says what the app does with a newer file or an unreadable part, and when the format number must rise. `docs/rates.md` lists every rate and dated rule in the code, with what to check each year and who publishes it.
- **A link to the app now shows a preview, and the tab has an icon.** The page carries a description, link preview tags, a theme colour and icons, all the app's own files.
- **Export the budget to Excel, CSV and PDF.** The Top sheet & budget tab has Export buttons beside the print buttons. Excel is a workbook with the top sheet, every line, the points schedule and the deal terms. CSV is the budget lines alone, and ProfitShare can read it back in: the sample comes back with the same 154 lines and the same $805,312.06. PDF is the top sheet and the full budget with page numbers. Pay type, account names and fringe rates of your own do not come back from a CSV. Text that looks like a formula is always written as text.
- **Download all my projects.** The Projects panel on the Start tab has a button that downloads every project in this browser as one .zip, each as its own .json file. Open takes the .zip, or several files at once, and brings each back as its own project.
- **What is saved to a file.** The Projects table says whether each project has been saved to a file, when, and whether it has changed since. A project with older changes that are in no file gets one quiet line with a Save button; dismiss it and it stays away for a few days.
- **Kept by the browser.** ProfitShare asks the browser, once, to keep its store when the disk runs low.
- **A two-minute tour and a glossary (a draft, for Cris to edit).** New here? The Start screen offers a six-step tour of the sample film, from top sheet to pitch deck; one click dismisses it for good. About now has a glossary of the words the app uses, searchable, each with its own link. It says how ProfitShare uses each word and is not legal advice.

Two independent reviews of the night's work found these, fixed the same morning:

- **A points line in an export carries no fringes.** The Excel, CSV and PDF exports gave a points line the fringes it would have had as wages, so the Total and Fringes columns added up to more than any figure in the app. A points line's total is now the value traded, and the columns add up to the top sheet.
- **An edit made just before switching project is kept.** Autosave waits a third of a second; opening a file, the sample or another project inside that moment left the last edit behind. The open project is now written first.
- **A full browser store is said plainly.** Opening a file or a .zip with no room left used to claim the projects had opened. It now says there is no room, and writes no record of a project it did not keep.
- **Smaller things.** A model list in an unexpected shape no longer breaks the key panel. The first edit to a sample that had sat untouched for days no longer brings the save reminder at once. The export help says what does not come back from a CSV. A failed export no longer asks for your project file in public. Four glossary definitions corrected where they said more than the app does.
- **PDF reading updated.** The part of the app that reads PDFs (scripts, brand books, look-book pages) is now the current version. Scenes, eighths and cast from a script PDF are read exactly as before. The decoders for JPEG 2000 and scanned black-and-white pictures are now two small files of the app's own, fetched only when a PDF has such a picture.
- **Typefaces in a sent deck.** The Latin font file is now chosen by what its rule says it covers, not by the order the rules are in.
- **The one-file build opens again.** Its security policy was written before the app's code was put into the page, so the page refused its own script. The policy is now worked out from the finished file.
- Tests run on the current jsdom (31).

## 2026-11-18

Eight things fixed before telling anyone the app exists. They came out of a full audit of the repo.

- **The sample agrees with itself.** *Salt Flat*'s budget said $811,758.05 in the file and the README, and $805,460 on screen once loaded, because five cast day counts typed into the sample's generator did not match its own stripboard (Lena had 12 days in the budget and 11 on the board). The generator now reads cast days from the board with the app's own code, so the two cannot drift. The sample totals **$805,312.06** everywhere. Tests fail if loading the sample ever changes a line again.
- **Spreadsheets are read by the app's own reader.** The `xlsx` library had two published high-severity flaws and no fixed version on npm, so it no longer ships in the app. A small reader of our own (with `fflate` to unzip) reads `.xlsx`, CSV and tab-separated files. It was checked cell by cell against the old library on both sample spreadsheets and 120 generated workbooks, and against zip bombs, broken files and files built to attack it. It has limits (50 MB, 500,000 filled cells) and every refusal is a plain sentence. **Old-format `.xls` files are no longer read**: the app asks you to save them as `.xlsx`. The first download is 290 KB smaller. `npm audit --omit=dev` reports nothing.
- **Addresses from a project file are checked.** A comparable film's source is a link only when it is an `http` or `https` address; anything else stays text. The call sheet's logo must be a picture carried in the file, and its colours must be plain colours, so a project someone sends you cannot make the app fetch anything.
- **The app page has a content security policy.** It allows the app's own files, `api.anthropic.com` and the two Google Fonts hosts, and nothing else: no outside requests, pictures, scripts or frames. It is built in at build time, with the one inline script allowed by a hash worked out from the page. It also allows WebAssembly, which the PDF reader needs for one kind of picture. The three-browser walk now fails on any violation.
- **A bad project file gets a plain answer.** "This project file is missing its budget lines", "This file was made by a newer version of ProfitShare", "This file cannot be read as a project. It may have been cut off", and so on, where there used to be a programmer's error. The parts a budget cannot exist without must be right or the file is refused; an optional part that cannot be read (the calendar, the call sheets, a picture) is left out or set back to its default, and the app says which. A project saved in the browser that cannot be read is skipped and left as it is, where before it could be overwritten by a blank one.
- **A crash shows a way out.** If the app fails while drawing, a screen says so, says the saved projects have not been deleted, and offers to download them all, go to the start screen, or reload. A project that crashed is not reopened by itself on the next start.
- **Tests run on pull requests.** A new Tests workflow runs the type check and the unit tests on every pull request, beside the browser walk.
- **The README describes the app as it is,** with screenshots, a plain statement of what the app covers and does not, and privacy in one place. The outdated demo video, its captions and its recording scripts are gone from the repo, and so are the saved critique notes.

Two independent reviews of the combined work found more, fixed the same day:

- **Two ways round the spreadsheet limits are closed.** A file could declare a part as empty while carrying a large one, or point two hundred sheets at one part, and unpack gigabytes or run for minutes. Both are refused as damaged. Text is now counted each time a cell uses it, so one huge string cited by thousands of cells is refused too.
- **A .csv saved by Excel on Windows reads properly.** Accented letters and £ signs in that older encoding came out as question marks.
- **A cut-off list of projects no longer hides them.** If the browser's list of saved projects cannot be read, it is rebuilt from the projects themselves, so they stay under Projects and in the crash screen's download.
- **Privacy wording matches what the app does.** The Pitch tab now says that PDFs you add go to Anthropic with a Draft, and About mentions the Google Fonts picker. The crash screen says the last few seconds of changes may not have been saved.
- A project file may hold up to 50 revenue scenarios.

- **Build and test tools brought up to date.** Vite 5 to 8, Vitest 2 to 5, esbuild 0.21 to 0.28, which clears every advisory in the tools used to build and test the app. Working on the code now needs Node 22.12 or newer. One slow spot turned up on the way: cutting a very long file name down for a ZIP did its sums again for every letter; it now counts once.

- **ProfitShare gets its own address,** profitshare.alonegirlmovie.com. The built app no longer assumes the folder it is served from, so the same build works there and at the old GitHub address. Projects saved in a browser at the old address stay there: open the old address, press Save on each, and Open them at the new one.

- **Projects in this browser folds away.** Click its heading on the Start tab to fold the list down to one line that says how many projects there are and which is open. The browser remembers how you left it.
- **Housekeeping.** The `.claude/` folder (a third-party design skill and its helper files, there for building the app, not part of it) is out of the repo. A test that read a sample brand sheet now names open fonts.

- **A tip jar.** ProfitShare is free and stays free. There is now a link to a tip jar under the ProfitShare name at the top of every page, in the footer, on the About tab, in the README, and as the Sponsor button on GitHub. It is a plain link to a Stripe page where you choose the amount; the app itself fetches nothing from Stripe.

- **Why ProfitShare exists.** The About tab now opens with Cris's own account of why she built it, and why it is free.

- **The app fits a phone.** Four tabs (Start, Call sheets, Points & waterfall, Pitch) used to push the whole page wider than the screen, and their tables squeezed columns down to one letter a line. Now the page never scrolls sideways: a table with more columns than the screen has room for scrolls inside its own box with its words kept whole, the Start screen's settings wrap, and the Design box on the Pitch tab stacks into one column.

- **Fields have names a screen reader can say.** About 490 fields, most of them in tables, were announced as just "edit text". Each now carries the name a sighted person already sees: the label beside it, or its column heading and the row it is on ("Days, Dana Okafor"). Nothing pressable is smaller than 24px any more, and the browser walk fails if a field or button on any tab has no name.

- **React 19 and TypeScript 7.** The app moves from React 18 to 19 and the compiler from TypeScript 5 to 7. Nothing changes on screen; the first download is 23 KB larger compressed. The PDF library and the test environment (jsdom) stay where they are for now: the newer PDF library ships its picture decoders as separate files and needs its own careful change, and the newer jsdom only changes how four tests have to be written.

Also: help text on the Deal tab and the look book no longer mentions a "Financing" tab or the report deck's layouts. Tests: 997 pass.

## 2026-11-17

It takes the first six in the look book, or the first six of one section (Tone, The world, Characters, References), or the ones you choose yourself, in the order you choose them. The slide lays out one to six pictures by how many there are, each cropped to its place with its caption and credit under it (a tick turns those off), and stacks them two across on a phone. A tick on the slide turns the agreement line off.

- **The report deck is gone.** The *Report deck* panel at the foot of the Pitch tab (the automatic printout, with its own preview, PDF and print) is removed, along with its code, its styles and the design options only it used (*Layout*, *Photo takes*, *Headings*, *Full-bleed look slides*, and the *Look slide* button in the look book). The pitch deck you build and send is the one deck now. The Pitch tab's *Print / save as PDF* (the investor summary on letter paper) is unchanged. A project saved with the old options still opens; they are simply no longer used. Tests: 790 pass.
- **No band along the bottom of a picture.** The footer of a picture slide (the film's name and the page number) no longer gets a faded band across the whole slide. Each of the two labels gets a small soft patch of its own, only when the picture behind it needs one, and nothing at all when it reads without. Tests: 793 pass.
- **A lighter shade behind the words.** On a picture slide the dark boxes behind the text are gone. The words now get one soft shade round each group of them (a heading and its paragraphs share one, with no step for every line), and the footer a thin band along the bottom in place of a block in each corner. The shade is read from the picture itself: the deck looks at what is behind each block of words and makes the shade only as dark as those words need to be readable (4.5 to 1, or 3 to 1 for large type), so a dusk sky gets next to nothing and pale salt gets more. It is never darker than before. The slider is now called *How much the whole picture is faded*, which is what it does. Where the picture cannot be read (it has not loaded, or a printed page), the slide falls back to the old shade.
- **Dark words on a pale picture.** When the picture behind the words is pale enough that light words would need a heavy shade, the slide turns its words round: dark words (the deck's background colour) straight on the picture, with little or no shade. A light deck does the reverse over a dark picture. The deck decides slide by slide, from the picture, and only turns a slide when that clearly needs less shade. Cards keep their own colours. Tests: 793 pass.
- **Shades of paper.** Papers now come in shades: *From my design* (the card colour, as before), *White*, *Cream*, *Aged*, *Kraft* and *Newsprint*, chosen for the deck beside *Paper for cards* and for any one slide beside its *Paper*. *Aged* is drawn to look like paper that has been in a drawer: uneven tone, browned edges and corners, a little foxing, creases on a letter, a browned tear on a torn page, faded rules in a notebook. It is all still drawn in code, and the ink is checked against the darkest tone the words can sit on. Old decks are unchanged.
- **Pictures show.** On a cover, a picture slide and a closing slide, the picture is no longer washed over evenly. The deck measures where the words sit and darkens (or, on a light deck, lightens) only behind them, with a soft edge; the rest of the picture is left nearly alone. The words keep the same contrast as before, by measurement, on any picture. *How much the picture is faded* now sets the light part.
- **The sample has pictures worth looking at.** Ten drawings made for *Salt Flat* by the sample script (the motel sign at dusk, the motel front, room 7, the flats, a low moon, dunes, the road out, the empty pool, last light, the wagon on the flats), all original, all generated as SVG. Its papers are the aged shade. Tests: 716 pass.

The app talks to no one until now, so it asks first: browsing loads previews from Google (which sees your computer's address and which fonts you look at, and nothing about your project); say *Not now* and the list still works by name. The font you pick is downloaded once and saved into your project, in the weights the deck uses (regular and bold, an italic for body text, or one file for a family that comes as a range), so the preview, the web deck and the PDFs carry it and a deck you send never needs Google. In its place, **a paper you choose**: plain, a postcard (with a stamp and a postmark, both wordless), letter paper with its folds, a ruled notebook page, a torn page, or *a mix* that deals them across a slide. *Paper for cards* under Design system sets it for the deck, with small live thumbnails; a slide with cards has its own *Paper* choice. Nothing else from the project is in the file: no budget lines, no other people, no undo history. The page carries a content policy that lets nothing load from outside and nothing run but the deck's own script, and what you typed is only ever placed as text. If something on the deck wants fixing, the download asks first: *Show me* or *Download anyway*. *Where to put it* explains three routes: attach it to an email, a file share that serves web pages, or your own site with a short address forwarded from your domain. You see the choice in words and press Apply or Cancel. The page says what is sent before it sends: your request, the kind of slide and your picture captions, never the pictures or the budget.
- **Help with the deck (optional, your own key).** *For a person*: paste a few lines about them and get a suggested cover line, note and which ask to show first, to edit before applying; what you paste is not kept. *Suggest a second line* gives three options under a headline. *Read my deck* lists what wants fixing, each linked to its slide; the checks that need no judgement (no source, overflow, an ask with no next step or contact, wording that reads like a promise of returns) run with no key and send nothing. ## 2026-11-16

A day of running a real project's numbers back through the app and fixing what the app let slip.

- **Deferred pay is paid.** A deferred line has always been described as a fixed IOU paid from first proceeds, and the waterfall never paid it: investors and the pool split every dollar. Now the deferred total comes off the top of each revenue scenario before the split, on the Points tab (a new row) and in the Pitch projections; the deck's cases use the same figures. A budget with no deferrals reads exactly as before.
- **Fiscal sponsor's fee.** Beside *Grants / fiscal sponsorship* on the Deal tab there is a *Sponsor's fee %*. A sponsor keeps a share of every donation (often 5 to 10%), so only the rest reaches the film; investors fund the difference. The deck's funding stack shows the sponsorship net of the fee. Files without the field are unchanged.
- **California credit: nothing before the letter.** Spending before the credit allocation letter is allowed but never qualifies. The credit now leaves out the prep days that fall before the letter (a prep line of N days runs backwards from the first day of photography, so only the working days between the letter and that day count) and any camera test the calendar puts before it. The Incentives tab says how much was left out, with a switch to count it anyway, and warns when no letter can arrive before the start date: rolling camera in California before the letter disqualifies the film.
- **Money that arrives after delivery is flagged.** A credit that is not bridged still comes off what investors put in, but it is not in the bank for the shoot. The Incentives tab now says how much someone has to front.
- **Where you shoot.** A new panel on the Deal tab: list the places and the shoot days in each, tick the ones outside the Los Angeles zone, pick each one's minimum wage. The share of days outside the zone feeds the California uplift (the field on the Incentives tab reads from the list once there is one), and the highest local minimum wage is what the non-shoot floor is checked against.
- **The wage floor knows the minimum wage.** The default floor for prep, wrap and post days is California's 2027 rate ($17.40) instead of 2026's $16.90, the starter's non-union background uses the same figure, and a floor under the highest local minimum shows a warning with a one-click raise. The City of Los Angeles ($18.42) and unincorporated LA County ($18.47) are presets.
- **Crew rates over budget: one click.** *As budgeted*, *+5%*, *+10%*, *+15%* buttons beside the percent box.
- **SAG pension & health check.** The SAG tab notes when the budget's SAG-AFTRA fringe and the tier's rate disagree (an imported budget can carry last year's).
- **The deck describes the right waterfall.** The investors' line on the ask slide said "recoup first" whatever the model; off the gross now reads as the split it is.
- The credit is figured against the latest letter that precedes the start whether or not its window has closed, so the number does not move the day a window shuts.
- **Funding paths (first stage of the pitch deck builder).** The engine can now say what investors have to fund, and what they get back in each case, under every on/off combination of the film's funding sources: grants and sponsorship, the California credit, the federal credit, local perks. `fundingSources`, `fundingPaths` and the pure `pathFor` (in `pathMath.ts`, which with `split.ts` depends on nothing else, so a deck can carry the same math). The path that is switched on reconciles with the Points tab and the Pitch projections to the cent. A budget that is fully covered now reads as nothing to fund instead of a stray fraction of a cent, and a negative grants figure in a hand-edited file counts as none. Nothing on screen changes yet.
- New tests in `financing.test.ts` and `paths.test.ts`; 145 pass.
- **The deck's data and its renderer (second stage of the pitch deck builder).** Two pieces, neither wired into the Pitch tab yet. `deckData(project)` (`src/engine/deckData.ts`) turns a project into one plain JSON object, the contract in `src/deck-runtime/data.ts`: the slides in order (thirteen layouts: cover, photo, text, cards, stats, timeline, comps, team, model, ways, numbers, ask, closing), the theme from the design system, the pictures the slides use, the people the deck is sent to, and the funding-path inputs from stage one. With no slides authored it builds a default order from what the Pitch tab already holds and skips what is empty. A stat with no source never reaches a deck; `deckWarnings` says why, and also flags a missing picture, too many cards, a link ending that is taken or reserved, revenue cases nobody typed and a budget already covered. The same project always gives the same deck (nothing reads the clock). `src/deck-runtime/` draws that JSON with no framework and no network, in a shadow root, so the in-app preview and the file you send will be the same code (`npm run build:deck-runtime`, about 28 kB). The numbers slide has a switch per funding source and recomputes what investors fund and what each case returns with the stage-one math; a recipient's link ending (`#name`, `#name-without`) sets their cover line, note, highlighted card and which ask leads, and nobody else's name is in what they see. Slides shrink to fit and say when they still overflow; text colours are derived from the theme until they pass 4.5:1 on its background, so a light or low-contrast theme stays readable; under 600px wide the deck becomes a stacked page for phones; keyboard paging, reduced motion, print (one slide per page) and a static mode for PDFs are in. Author text is only ever set as text, colours, fonts and picture addresses are checked before use, and a hand-edited or hostile file drops what it cannot read instead of failing. `npm run deck:scratch` writes a test page from a deck JSON and never carries more than one recipient. Old project files are untouched: the new Pitch fields are optional and the report deck is unchanged.
